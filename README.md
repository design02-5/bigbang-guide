# BIGBANG 應援指南（骨架版）

BIGBANG 2026-2027 WORLD TOUR「XX : COSMOS」歌迷自製應援指南。
純 HTML/CSS/原生 JS，不需要 Node.js、不需要建置工具，直接是靜態網站。

參考原型：VAUNDY 台北場應援指南（歌迷自製，非官方，同類型專案的常見做法）。

---

## 目前是「骨架」，不是正式版

所有標示 **[待補]** 或畫面上顯示灰底小標籤的地方，都是佔位資料，不是真實內容：

- 場次城市、日期、時間、票價、售票連結
- 座位配置圖
- 交通方式細節
- 歌單（目前只有 5 首示範曲目，歌名和歌詞都是佔位文字，不是真實歌詞）
- YouTube 影片 ID（目前全部留空，畫面會顯示「尚未設定影片」）

**功能都已經做好**（巡演場次清單、倒數計時、搜尋/排序、歌詞同步捲動、卡拉OK高亮、羅馬拼音/原文/中文切換、只聽大合唱模式、簡潔模式、深色模式、分享、寬螢幕雙欄版型），
之後只要把 `js/data.js` 裡對應欄位換成真實資料，畫面會自動更新，不需要碰版面程式碼。

**視覺風格**參考官方主視覺（黑白顆粒感、無限圓環紋理、粗黑體大寫排版），不是原本 VAUNDY 參考站的金色配色。

**倒數計時／演出資訊手風琴／官方網站按鈕**目前先隱藏（`data.js` 裡 `showCountdown`／`showInfoSections`／`showOfficialSiteLink` 都是 `false`），之後要顯示改成 `true` 即可，不用改版面程式碼。

## 怎麼預覽

**雙擊 `啟動本機預覽.bat`**，會自動開瀏覽器連到本機預覽網址（黑色視窗保持開著，關掉視窗就停止預覽）。

> ⚠️ **不要直接雙擊 `index.html`**：那樣網址會是 `file://` 開頭，YouTube 影片區塊會顯示「影片播放器設定錯誤（錯誤 153）」——這是 YouTube 內嵌播放器的限制，只要不是透過 `http://` 開啟就無法運作，跟網站本身壞掉無關。除此之外像分享、複製地址這類功能也會失效。用 `.bat` 啟動、或之後部署到 GitHub Pages（`https://`）都完全正常。

### 用平板/手機編輯歌詞（跟這台電腦同一個 Wi-Fi）

`啟動本機預覽.bat` 開著的那個黑色視窗，一開始就會印出平板要輸入的網址，例如：

```
http://192.168.1.83:8888/
http://192.168.1.83:8888/tools/lyrics-builder.html
```

平板/手機連同一個 Wi-Fi，瀏覽器直接輸入那個網址就能用，包括 lyrics-builder 的「儲存回 data.js」也完全可以用（存檔還是寫回這台電腦的硬碟）。

- 每次那個 IP 可能不一樣（電腦重開 Wi-Fi、換網路都可能變），照黑色視窗當下印出來的網址為準。
- 第一次從平板連線時，這台電腦的 Windows 可能會跳出防火牆詢問視窗，選「允許」（私人網路）才能連得進來。
- 這個網址只有同一個 Wi-Fi 底下的裝置能連，跟 GitHub Pages 那個對外網址是兩回事——GitHub Pages 只能看，不能存檔。

## 怎麼填資料

只需要改 `js/data.js` 這一支檔案：

1. **`TOUR_STOPS`**：巡演全場次清單（目前已經照官方主視覺海報填了全部 19 場真實城市/日期/場館）。首頁只會顯示 `dateEnd`（該場次最後一天）還沒過期的場次，過期會自動從清單消失，不用手動刪。之後官方加場、改期，直接改這個陣列就好。
2. **`TOUR_INFO`**：團名、巡演名稱、交通方式、應援禮儀文案（已經寫好通用版，可依需要調整語氣）。因為是多城市巡演，`venue`／`venueAddress` 等單一場館欄位目前只在「演出資訊」手風琴（現在是關閉狀態）用得到。
   - `seatMapImage` 放圖片路徑（先把圖片放進 `images/` 資料夾）。
3. **`SONGS`**：整批歌單。每首歌的 `lyrics` 陣列是逐句歌詞，`time` 是「這句歌詞在 YouTube 影片裡的秒數」，用來做點擊跳轉與自動高亮同步——**新增歌曲不用手動寫這段 JS，請用 `tools/lyrics-builder.html`（見下方說明）**。
   - `categories`：自訂分類標籤（例：`["舞曲"]`、`["抒情","安可曲"]`），名稱完全自訂、可以有多個。應援指南頁會自動列出目前所有分類當篩選按鈕（可多選，OR 邏輯——選了多個分類，符合其中任一個就會顯示），沒有任何歌設分類時篩選列會自動隱藏。
   - **大合唱／應援詞用不同顏色標記**（金色／藍色），`chant` 設定值就會決定整句顏色。如果一句裡只有幾個字是應援詞、其他是正常歌詞（例如「이 난장판에 HEY」只有 HEY 是喊的），把要上色的部分用 `**` 包起來即可，例如 `original: "이 난장판에 **HEY**"`——只有 `**...**` 裡面的字會上色，其他字維持正常顏色。沒有加 `**` 的句子維持整句上色（跟原來一樣）。這個語法直接打在 `original`／`romaji`／`zh` 文字裡就好，`tools/lyrics-builder.html` 的輸入框也可以直接這樣打，不用改工具。
4. **`CHANT_TYPES`**：應援類型的中文標籤，目前是「大合唱／應援詞／拍手／揮手／跳躍／轉臂」，如果社群慣用其他講法可以直接改 `label`（不要改 `key`）。

## 新增/修改歌曲：歌詞建置工具（不用問我，也不用手寫 JS）

雙擊 `啟動本機預覽.bat` 開著的狀態下，瀏覽器網址列輸入
`http://localhost:8888/tools/lyrics-builder.html`（不能直接雙擊那個 html 檔案，原因跟上面「怎麼預覽」一樣）。

**新增一首新歌：**
1. 填歌曲基本資料（id／排序／曲名／YouTube 影片 ID），按「載入/更新影片」。
2. 邊播影片邊按「＋ 用目前時間新增一句」，每按一次就用目前播放秒數新增一列——不用自己算時間點。
3. 把準備好的原文/羅馬拼音/中文歌詞，各自整理成「一行一句」貼進三個欄位，按「套用文字到目前列表」，會照順序自動填進每一列（行數要跟列表列數一樣才會套用）。
4. 每一列右邊點選對應的應援類型（大合唱/應援詞/拍手/揮手/跳躍/轉臂），沒有就留「無」。
5. 按「產生程式碼」→「儲存回 data.js」，會直接寫進本機的 `js/data.js`（存檔前自動備份成 `data.js.bak`）。

**修改已經做好的歌：**
最上面「⓪ 選擇要修改的歌」下拉選單直接選那首歌（會自動讀 `data.js` 目前的歌單），選了就自動帶入所有欄位跟影片，改完照樣走④⑤，按「儲存回 data.js」即可，不用複製貼上。

存完之後，照下面「部署到 GitHub Pages」的 TortoiseGit 步驟 commit + push，正式網站才會更新。

### 手機／平板／外面電腦編輯歌詞（不用連這台電腦、不用等回家）

上架 GitHub Pages 之後（見下一節），`lyrics-builder.html` 可以改成直接讀寫 GitHub 上的 `js/data.js`，
不用透過這台電腦的本機伺服器，任何裝置、任何地方（只要能上網）都能用：

1. 到 [github.com/settings/tokens](https://github.com/settings/tokens) → **Generate new token (classic)**，
   勾選 `repo` 權限，產生一組 token（`ghp_` 開頭那串字，只會顯示一次，先複製起來）。
2. 開 `https://你的帳號.github.io/repo名/tools/lyrics-builder.html`，找到「🌐 GitHub 存檔設定」，
   填帳號、repo 名稱、分支（預設 `main`）、貼上剛剛那組 token，按「儲存設定到這台裝置」。
3. 之後在**這台裝置**上開這個頁面，讀取歌單、儲存都會直接 commit 到 GitHub，畫面下方會顯示
   「目前：GitHub 模式已啟用」。存檔後 GitHub Pages 大約 1-2 分鐘才會重新部署到正式網站。
4. 每台要編輯的裝置（手機/平板/另一台電腦）都要各自貼一次 token——token 只存在那台裝置的瀏覽器裡，
   不會存進 data.js、也不會同步到別的裝置。裝置遺失或不想再用了，到 GitHub 網站的 tokens 頁面撤銷即可。
5. 沒設定 token 的裝置（例如這台電腦，沒特別去填）就照舊用本機伺服器模式，兩種模式不衝突，各自獨立記在各裝置的瀏覽器裡。

## 部署到 GitHub Pages（TortoiseGit 操作）

1. 在 `BIGBANG應援指南` 資料夾（本資料夾）上按右鍵 → **TortoiseGit → Git Create Repository Here**。
2. 到 GitHub 網站建立一個新的空 repository（不要勾選自動產生 README）。
3. 資料夾按右鍵 → **TortoiseGit → Settings → Remote**，新增一個 remote 叫 `origin`，網址填剛建立的 repo 網址。
4. 資料夾按右鍵 → **TortoiseGit → Add**，把所有檔案加入版控。
5. 資料夾按右鍵 → **TortoiseGit → Commit →「master」**，寫一句 commit 訊息（例如「初始骨架」）送出。
6. 資料夾按右鍵 → **TortoiseGit → Push**，把內容推上 GitHub。
7. 到 GitHub 網站該 repo 的 **Settings → Pages**，Source 選 `main`（或 `master`）分支、根目錄 `/`，儲存後 GitHub 會給一個 `https://<帳號>.github.io/<repo名稱>/` 網址，就是正式對外的網址。
8. 之後每次改完 `data.js` 或其他檔案，一樣用 **TortoiseGit → Commit → Push** 兩步就會自動更新到那個網址（GitHub Pages 會自動重新部署，通常 1-2 分鐘生效）。
